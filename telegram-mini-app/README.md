# TB Telegram Mini App

Отдельный frontend-модуль для персональных и административных настроек Telegram-бота TB.

## Граница текущего этапа

Mini App развивается параллельно с существующим Telegram-интерфейсом. На этом этапе:

- текущие команды, кнопки и формы настроек в боте не удаляются;
- Mini App не добавляется в меню бота;
- существующие JSON/SQLite-хранилища не меняются;
- опасные административные действия заблокированы до появления защищённых backend endpoint;
- без `VITE_API_BASE_URL` приложение работает на локальных mock-данных.

Интеграция и очистка старых графических элементов бота выполняются только после завершения и отдельного решения о выпуске Mini App.

## Реализованные разделы

### Общие настройки

- русский или английский язык;
- компактный или подробный формат уведомлений.

### FVG

- включение всего модуля;
- подтверждённые FVG;
- предварительные FVG T−3;
- бычьи и медвежьи направления;
- добавление и удаление инструментов;
- включение отдельного инструмента;
- ценовой диапазон для каждого инструмента;
- минимальный размер FVG;
- единицы размера: USD или проценты;
- область применения каждого фильтра: T−3, подтверждённые, бычьи и медвежьи сигналы.

### Funding alerts

- включение рассылки;
- частота от 15 до 2880 минут с шагом 15 минут;
- минимальный абсолютный процент;
- положительный и отрицательный фандинг;
- Bitunix, Binance, Bybit, BingX, Bitget и Gate;
- защита от отключения всех направлений или всех бирж.

### Администрирование

- публичный или приватный режим;
- представление allowlist;
- WebSocket, outbox, ошибки доставки, базы и версия;
- подготовленные, но заблокированные действия backup и restart.

## Стек

- React 19;
- TypeScript;
- Vite;
- Telegram WebApp API без внешней UI-библиотеки.

Интерфейс адаптирован под Telegram WebView, safe-area, светлую/тёмную системную тему Telegram и haptic feedback.

## Локальный запуск

```bash
cd telegram-mini-app
cp .env.example .env
npm install
npm run dev
```

Открыть `http://localhost:5173`. При пустом `VITE_API_BASE_URL` используется mock-режим.

Проверка:

```bash
npm run typecheck
npm run build
```

## Backend API

Frontend ожидает два endpoint:

```text
GET /api/mini-app/settings
PUT /api/mini-app/settings
```

Telegram `initData` отправляется в заголовке:

```text
X-Telegram-Init-Data: <window.Telegram.WebApp.initData>
```

Backend обязан:

1. проверить подпись `initData` токеном бота;
2. получить Telegram ID только из проверенного `initData`;
3. загрузить и нормализовать данные из текущих хранилищ;
4. валидировать все изменения повторно на сервере;
5. проверять `ADMIN_TELEGRAM_IDS` при каждом административном запросе;
6. сохранять изменения атомарно;
7. не принимать Telegram ID из JSON-body как источник авторизации.

Полное отображение полей описано в [`API_CONTRACT.md`](API_CONTRACT.md).

## Предлагаемая последовательность интеграции

1. Реализовать read-only endpoint и подключить реальные настройки.
2. Добавить сохранение общих настроек.
3. Подключить FVG-настройки и серверную валидацию фильтров.
4. Подключить funding alerts и выбранные биржи.
5. Реализовать отдельные подтверждаемые admin endpoint.
6. Добавить HTTPS-размещение Mini App.
7. Подключить Web App URL в BotFather и тестовую кнопку только для администратора.
8. Провести параллельный тест с текущим Telegram UI.
9. После полного принятия переключить настройки на Mini App и удалить только ставшие лишними элементы бота.
