# Историческая проверка качества FVG

Бот не содержит правил входа, stop-loss и take-profit. Поэтому инструмент не
выдумывает P&L и не называет FVG прибыльной стратегией. Он измеряет только
наблюдаемые свойства подтверждённых событий после закрытия свечи C.

## Что измеряется

Для каждого подтверждённого FVG на `15m`:

- первый вход будущей цены в зону (`touch`);
- первое полное перекрытие зоны (`full fill`);
- число свечей до touch/full fill;
- MFE — максимальное благоприятное движение от `close(C)`;
- MAE — максимальное неблагоприятное движение от `close(C)`;
- результаты отдельно на горизонтах 1, 4, 16 и 96 свечей;
- разбивка по направлению, месяцу и размеру зоны.

Для бычьего FVG:

- touch: `low будущей свечи <= верхней границы зоны`;
- full fill: `low будущей свечи <= нижней границы зоны`.

Для медвежьего правила симметричны через `high`.

Свечи A/B/C никогда не включаются в будущий outcome. Анализ начинается строго
со свечи после C, поэтому обычного look-ahead в расчёте touch/MFE/MAE нет.

## Загрузка истории Bitunix

```bash
.venv/bin/python download_bitunix_history.py \
  --symbol BTCUSDT \
  --interval 15m \
  --start 2025-01-01 \
  --end 2026-01-01 \
  --output data/historical/btcusdt_15m_2025.csv
```

Загрузчик использует публичный REST API, общий rate limiter и лимит страницы
Bitunix 200 свечей. API-ключ не нужен.

## Запуск отчёта

```bash
.venv/bin/python run_fvg_quality_backtest.py \
  --data-file data/historical/btcusdt_15m_2025.csv \
  --symbol BTCUSDT \
  --horizons 1,4,16,96 \
  --output data/reports/btcusdt_fvg_quality_2025.json
```

Чтобы сохранить individual outcomes для последующего анализа:

```bash
.venv/bin/python run_fvg_quality_backtest.py \
  --data-file data/historical/btcusdt_15m_2025.csv \
  --symbol BTCUSDT \
  --include-events \
  --output data/reports/btcusdt_fvg_events_2025.json
```

## Формат CSV

Обязательные поля:

```text
time,open,high,low,close
```

`time` может быть Unix timestamp в секундах/миллисекундах или ISO-8601. Строки
сортируются, дубликаты времени заменяются последней строкой. Некорректные,
неположительные и non-finite цены приводят к явной ошибке, а не пропускаются
незаметно.

## Как читать отчёт

`eligible_events` на каждом горизонте может отличаться. Событие в конце файла
не включается в горизонт 96, если после него доступно меньше 96 свечей. Поэтому
проценты touch/fill считаются от своего честного denominator.

MFE/MAE — исследовательские характеристики, а не доходность. Для P&L сначала
нужно отдельно зафиксировать entry, invalidation/stop, target, комиссии,
проскальзывание и правило неоднозначной свечи, а затем валидировать это как
отдельную стратегию.
