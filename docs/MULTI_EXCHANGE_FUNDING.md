# Мультибиржевой фандинг

## Подключённые источники

Бот получает текущие ставки USDT perpetual без API-ключей:

- Bitunix;
- Binance;
- Bybit;
- BingX;
- Bitget;
- Gate.

Все значения приводятся к единой единице отображения: процентным пунктам. Например,
ставка API `0.0001` отображается как `0.01%`. Bitunix уже возвращает ставку в
процентных пунктах, поэтому дополнительное умножение для него не выполняется.

## Просмотр

В `/funding` над пагинацией расположены переключатели бирж. Выбранная биржа
помечается галочкой и запоминается отдельно для пользователя Telegram.

Кнопка обновления загружает свежие данные только для открытой биржи. Служебная
задача каждые 15 минут загружает все подключённые биржи параллельно и сохраняет по
одной общей копии данных, а не по отдельной полной копии на пользователя.

## История снимков

Каждый плановый 15-минутный запрос записывает общий мультибиржевой снимок в
`data/funding_alerts.sqlite3`. Снимок хранится как сжатый JSON, поэтому не создаёт
тысячи отдельных строк на каждый инструмент.

В таблице `funding_snapshot_history` всегда остаются только три последних снимка.
После четвёртой загрузки самый старый снимок удаляется в той же транзакции. Размер
таблицы поэтому стабилизируется и не растёт вместе со временем работы бота.

Ручная кнопка `🔎 Проверка фандинга` обновляет оперативный кеш, но не добавляет
отдельную запись в историю.

## Проверка инструмента

Кнопка `🔎 Проверка фандинга` переводит бот в режим ввода инструмента. Допустимы
форматы `BTC`, `BTCUSDT`, `BTC/USDT`, `BTC-USDT` и `BTC_USDT`; они нормализуются к
формату `BTCUSDT`.

После ввода бот получает свежий снимок всех подключённых бирж и показывает по каждой:

- текущую ставку фандинга;
- изменение цены за 24 часа, когда оно доступно;
- отметку об отсутствии контракта;
- отметку о временной недоступности API.

## Уведомления

Частота уведомлений задаётся от 15 минут до 48 часов с шагом 15 минут. Существующие
часовые настройки автоматически переводятся в минуты без изменения фактической
частоты: например, 4 часа становятся 240 минутами.

При обновлении активный пользователь ставится на ближайшую четверть часа. После
этого расписание сохраняет выбранный шаг без накопления дрейфа.

В настройках уведомлений каждая биржа включается или выключается отдельной
галочкой. Нельзя снять последнюю галочку.

Расписание, порог и направления хранятся в существующей таблице настроек. Выбор
бирж и состояние пересечений находятся в отдельных ограниченных таблицах той же
базы `data/funding_alerts.sqlite3`.

При обновлении существующие Bitunix-настройки сохраняются. Активные пересечения
Bitunix один раз переносятся в мультибиржевую таблицу, чтобы обновление не создавало
повторные сигналы.

Если одна биржа временно недоступна, бот сохраняет её предыдущее состояние
пересечений и не воспринимает ошибку API как возврат ставки под порог. Остальные
доступные биржи продолжают обрабатываться.

## Публичные API следующего этапа

OKX и KuCoin также предоставляют публичную информацию о фандинге, но текущие
эндпоинты запрашиваются по отдельному контракту. Их следует подключать через
ограниченную очередь запросов и кеш списка инструментов, а не сотнями одновременных
запросов каждые 15 минут.
