# Project reliability and performance audit — 2026-08-11

## Scope

Audit of the current FVG Alert Bot codebase, including Telegram update handling, SQLite lifecycle and hot paths, Telegram Mini App backend, market-overview failure isolation, GitHub Actions runner routing, release safety, and regression coverage.

## Runtime fixes

- `FundingExchangeStore` explicitly closes context-managed SQLite connections.
- Funding exchange selection replacement and crossing-state reset are atomic.
- Persistent SQLite WAL mode is configured during database initialization instead of on every hot-path connection in the primary FVG/funding stores.
- Telegram update activity tracking reuses a process-wide `UserActivityRegistry`.
- Synchronous Mini App settings/admin storage is moved out of the aiohttp event loop.
- aiohttp application state uses typed `web.AppKey` values.
- Malformed persisted instruments and individual malformed ticker rows fail soft instead of taking down the whole market overview.
- Read-only SQLite probes in Mini App diagnostics/admin settings are explicitly closed.

## Quality controls added

- Regression tests cover connection lifecycle, atomic funding state replacement, off-loop Mini App storage, shared activity registry, malformed market rows, and WAL initialization.
- Repository-wide AST regression prevents unsafe direct `with sqlite3.connect(...)` usage unless an explicit closing connection factory is used.
- Test fixtures that previously leaked SQLite connections now close them explicitly while preserving commit semantics.

## CI and release safety

- Workflow runners are restricted to the documented exact self-hosted selector allowlist.
- Fast checks use `[self-hosted, fast]`.
- Linux/systemd/release checks use `[self-hosted, Linux]`.
- Release publication preflights `sha256sum`, `tar`, and `gh`.
- Existing immutable tags must never be moved or republished from another commit.

## Integration note

PR #95 landed while this audit was in progress and introduced the `1.3.7` Telegram Mini App menu-button preservation fix. The audit branch was synchronized with that `main` change and must preserve the menu-button behavior. Because `v1.3.7` is already immutable, the audit fixes require a later patch version rather than reusing that tag.

## Production boundary

This audit does not deploy the VDS or modify `/etc/fvg-alert-bot.env`, `/var/lib/fvg-alert-bot`, BotFather settings, Xray, or external port 443. Production deployment remains a separate guarded operation after an audited release commit is merged and published.
