# FVG Alert Bot 1.1.0

Дата подготовки базового релиза: 27 июля 2026 года.

## Текущее funding-поведение в `main`

Бот поддерживает персональные уведомления о фандинге Bitunix, Binance, Bybit,
BingX, Bitget и Gate. Пользователь может настроить интервал от 15 минут до 48 часов
с шагом 15 минут, минимальный абсолютный процент, направления и набор бирж.

Общий мультибиржевой снимок загружается каждые 15 минут на границах `:00`, `:15`,
`:30` и `:45` UTC. Для каждого пользователя применяется собственное расписание.
Повторное сообщение не отправляется, пока инструмент остаётся за порогом; новое
уведомление появляется после возврата в диапазон и следующего пересечения.

Существующие часовые интервалы автоматически мигрируют в минуты без изменения
фактической частоты. Например, настройка `4 часа` становится `240 минут`.

## Хранение

Funding-данные находятся в SQLite/WAL-базе:

```text
data/funding_alerts.sqlite3
```

В ней хранятся:

- пользовательские настройки;
- выбранные биржи;
- текущее состояние пересечений;
- три последних полных мультибиржевых снимка.

Плановый снимок сохраняется как сжатый JSON. При добавлении четвёртого снимка самый
старый удаляется в той же транзакции, поэтому история не растёт со временем.
Ручная проверка инструмента не добавляет запись в историю.

Устаревшие пересечения удаляются через 7 дней, выключенные неактивные настройки —
через 180 дней. Раз в сутки выполняются checkpoint и incremental vacuum.

## Подготовка VDS

- backup-скрипт делает согласованные SQLite-снимки обеих баз через backup API;
- live-файлы `funding_alerts.sqlite3-wal` и `funding_alerts.sqlite3-shm` не копируются в архив;
- `scripts/update_vds.sh` выполняет preflight, предварительный backup,
  fast-forward обновление, атомарную установку и post-deploy проверку;
- после установки проверяются systemd, версия, runtime-ссылка и `PRAGMA quick_check`;
- установленный Git commit записывается в `/opt/fvg-alert-bot/BUILD_COMMIT`.

## Обновление существующего сервера

```bash
ssh root@IP_АДРЕС_СЕРВЕРА
cd /root/TB
git fetch origin --prune
git checkout main
git pull --ff-only origin main
EXPECTED_VERSION=1.1.0 bash scripts/update_vds.sh
```

Скрипт сам создаёт backup до остановки бота и затем запускает существующий
атомарный установщик. Runtime-state в `/var/lib/fvg-alert-bot` и секреты в
`/etc/fvg-alert-bot.env` сохраняются.

## Проверка

```bash
cat /opt/fvg-alert-bot/VERSION
cat /opt/fvg-alert-bot/BUILD_COMMIT
systemctl is-active fvg-alert-bot
systemctl is-enabled fvg-alert-bot
journalctl -u fvg-alert-bot -n 100 --no-pager
ls -lah /var/backups/fvg-alert-bot
```

Ожидаемая версия:

```text
1.1.0
```

В Telegram откройте `/funding` → `🔔 Уведомления`, задайте интервал `15` и
проверьте, что следующая контрольная точка назначена на ближайшие `:00`, `:15`,
`:30` или `:45` UTC.

Количество сохранённых снимков:

```bash
sqlite3 /var/lib/fvg-alert-bot/data/funding_alerts.sqlite3 \
  "SELECT COUNT(*) FROM funding_snapshot_history;"
```

Результат не должен превышать `3`.

## Rollback

Установщик сохраняет предыдущий релиз в `/opt/fvg-alert-bot.previous`. Если новый
процесс не запускается, rollback выполняется автоматически. Ручная процедура
описана в [`VDS_DEPLOYMENT.md`](VDS_DEPLOYMENT.md).
