# Мультибиржевой модуль FVG

## Пользовательская модель

Один FVG-инструмент — уникальная комбинация биржи и торговой пары. Например, `BTCUSDT` на Binance и `BTCUSDT` на Bybit считаются двумя инструментами.

Для каждого инструмента сохраняются:

- биржа;
- нормализованный символ;
- фиксированный таймфрейм `15m`;
- статус уведомлений;
- дата создания;
- фильтры цены и размера.

Лимит составляет 10 инструментов на Telegram ID. Проверка лимита и добавление выполняются внутри одной атомарной транзакции хранилища настроек.

## Единая политика свечей

Для Bitcoin и всех остальных активов FVG-модуль использует только закрытые 15-минутные свечи.

Это означает:

- минутные свечи `1m` не запрашиваются;
- таймфреймы `1h`, `4h`, `1d` не участвуют в FVG-сканировании;
- Bitunix WebSocket подписывается только на `market_kline_15min`;
- Bitunix REST recovery запрашивает только `15m`;
- мультибиржевой REST poller принимает только `15m` и отсекает другой интервал до сетевого запроса;
- один подтверждённый FVG рассчитывается по трём последовательным закрытым 15-минутным свечам.

Публичные свечи загружаются через единый адаптер для:

- Bitunix;
- Binance;
- Bybit;
- BingX;
- Bitget;
- Gate.

## Пред-FVG

Функция пред-FVG отключена и больше не используется в production runtime.

Удалены активные источники предварительных сигналов:

- нет минутной подписки Bitunix;
- нет минутного REST recovery;
- нет предварительного multi-exchange polling;
- нет job `fvg-pre-control-t-minus-3`;
- нет пользовательской команды `/fvg_pre_alert`;
- нет кнопок пред-FVG в настройках и фильтрах;
- нет предварительных уведомлений.

Тип `PRE_FVG` и старые поля настроек могут оставаться в низкоуровневых моделях и исторических данных только для чтения старой истории и совместимости с уже сохранёнными событиями. Новые события этого типа не создаются и пользователям не доставляются.

## Совместимость настроек

Существующие пользовательские настройки автоматически интерпретируются как 15-минутные:

- сохранённые `1h`, `4h`, `1d` нормализуются до `15m` в активном runtime;
- `notify_pre_fvg` принудительно считается выключенным;
- фильтры применяются только к подтверждённым FVG;
- старые Bitunix-ключи и идентификаторы событий сохраняются, чтобы обновление не вызвало повторную рассылку.

Это позволяет перейти на облегчённый режим без потери существующих инструментов пользователя.

## Рыночные расчёты

Планировщик формирует уникальный набор `биржа + символ`, запрашивает только `15m`, рассчитывает подтверждённый FVG один раз и затем выбирает всех подходящих получателей. Персональные фильтры не запускают повторный рыночный расчёт.

Подтверждённое событие создаётся только после закрытия свечи C. Незакрытая свеча не создаёт уведомление.

## Доставка и защита от дублей

Существующий SQLite/WAL event store и persistent outbox сохранены. Уникальный идентификатор события включает биржу для новых площадок. Формат старого Bitunix ID не изменён.

Это обеспечивает:

- идемпотентную запись событий;
- отсутствие повторной доставки одному пользователю;
- сохранение очереди после перезапуска;
- повторные попытки при временных ошибках Telegram;
- прекращение повторов после постоянного отказа Telegram.

## Telegram-интерфейс

Добавление проходит последовательно:

1. выбор биржи;
2. ввод и проверка торговой пары;
3. экран проверки с фиксированным таймфреймом 15 минут;
4. явное подтверждение.

Карточка инструмента позволяет поставить уведомления на паузу или удалить инструмент. Выбор таймфрейма и настройки пред-FVG отсутствуют.

FAQ вынесен в отдельную вкладку и объясняет добавление инструмента, подтверждение FVG на закрытой 15-минутной свече и лимит 10 инструментов.
