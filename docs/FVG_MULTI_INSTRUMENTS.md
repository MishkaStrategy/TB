# Мультибиржевой модуль FVG

## Пользовательская модель

Один FVG-инструмент — уникальная комбинация биржи и торговой пары. Например, `BTCUSDT` на Binance и `BTCUSDT` на Bybit считаются двумя инструментами.

Для каждого инструмента сохраняются:

- биржа;
- нормализованный символ;
- выбранные таймфреймы `15m`, `1h`, `4h`, `1d`;
- статус уведомлений;
- дата создания;
- фильтры цены и размера.

Лимит составляет 10 инструментов на Telegram ID. Несколько таймфреймов одного инструмента занимают одно место. Проверка лимита и добавление выполняются внутри одной атомарной транзакции хранилища настроек.

## Единая политика рыночных данных

Для Bitcoin и всех остальных активов биржевой источник FVG использует только закрытые 15-минутные свечи.

Из этих данных бот локально строит свечи старших таймфреймов:

- `1h` = 4 последовательные `15m` свечи;
- `4h` = 16 последовательных `15m` свечей;
- `1d` = 96 последовательных `15m` свечей.

Агрегация выполняется по UTC-границам таймфреймов. Свеча старшего таймфрейма считается полной только при наличии всех необходимых последовательных закрытых 15-минутных свечей. Неполный набор данных не создаёт FVG.

Таким образом:

- минутные свечи `1m` не запрашиваются;
- прямые запросы `1h`, `4h`, `1d` к биржам не нужны для FVG;
- Bitunix WebSocket подписывается только на `market_kline_15min`;
- Bitunix REST recovery запрашивает только `15m`;
- мультибиржевой poller загружает `15m` и локально рассчитывает выбранные таймфреймы;
- если в одной контрольной точке для рынка закрылись несколько таймфреймов, один общий набор `15m` используется для всех этих расчётов.

Публичные свечи поддерживаются через единый адаптер для:

- Bitunix;
- Binance;
- Bybit;
- BingX;
- Bitget;
- Gate.

Для длинного дневного lookback Bitunix использует существующую пагинацию исторических `15m` свечей, потому что один запрос Bitunix ограничен 200 свечами.

## Подтверждённые FVG

Поддерживаемые таймфреймы FVG:

- `15m`;
- `1h`;
- `4h`;
- `1d`.

На каждом таймфрейме FVG определяется по трём последовательным закрытым свечам A, B и C. Уведомление создаётся только после закрытия свечи C. Незакрытая или неполная свеча не может подтвердить сигнал.

Расписание расчётов:

- `15m` — каждые 15 минут;
- `1h` — на границе часа;
- `4h` — в 00:00, 04:00, 08:00, 12:00, 16:00 и 20:00 UTC;
- `1d` — в 00:00 UTC.

## Пред-FVG

Функция пред-FVG отключена и не используется в production runtime.

Нет:

- минутной подписки Bitunix;
- минутного REST recovery;
- предварительного multi-exchange polling;
- job `fvg-pre-control-t-minus-3`;
- пользовательской команды `/fvg_pre_alert`;
- кнопок пред-FVG в настройках и фильтрах;
- предварительных уведомлений.

Тип `PRE_FVG` и старые поля могут оставаться в низкоуровневых моделях и исторических данных только для совместимости с уже сохранённой историей. Новые события этого типа не создаются.

## Совместимость настроек

Существующие выбранные таймфреймы сохраняются. Облегчённая политика относится к источнику данных, а не к доступным FVG-таймфреймам.

- сохранённые `15m`, `1h`, `4h`, `1d` продолжают определять, какие подтверждённые FVG получает пользователь;
- `notify_pre_fvg` принудительно считается выключенным;
- фильтры применяются к подтверждённым FVG выбранного инструмента независимо от его таймфрейма;
- старые Bitunix-ключи и идентификаторы событий сохраняются, чтобы обновление не вызвало повторную рассылку.

## Рыночные расчёты

Планировщик каждые 15 минут определяет, какие выбранные таймфреймы действительно закрылись в текущую UTC-контрольную точку. Затем он группирует расчёты по `биржа + символ`.

Для каждого рынка выполняется один общий запрос 15-минутных свечей с глубиной, достаточной для самого крупного из нужных таймфреймов. После этого `15m`, `1h`, `4h` и `1d` рассчитываются локально из одного набора данных.

Персональные фильтры пользователей не создают повторных запросов к бирже и не запускают повторный рыночный расчёт.

## Доставка и защита от дублей

Существующий SQLite/WAL event store и persistent outbox сохранены. Уникальный идентификатор события включает таймфрейм и биржу для новых площадок. Формат старого Bitunix ID остаётся совместимым.

Это обеспечивает:

- идемпотентную запись событий;
- отсутствие повторной доставки одному пользователю;
- сохранение очереди после перезапуска;
- повторные попытки при временных ошибках Telegram;
- прекращение повторов после постоянного отказа Telegram.

## Telegram-интерфейс

Добавление инструмента проходит последовательно:

1. выбор биржи;
2. ввод и проверка торговой пары;
3. выбор одного или нескольких таймфреймов `15m / 1h / 4h / 1d`;
4. экран проверки;
5. явное подтверждение.

Карточка инструмента позволяет изменить таймфреймы, поставить уведомления на паузу или удалить инструмент. Настроек пред-FVG нет.

FAQ отдельно поясняет, что с бирж загружаются только 15-минутные свечи, а старшие FVG-таймфреймы строятся локально.
