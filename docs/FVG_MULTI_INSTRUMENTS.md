# Мультибиржевой модуль FVG

## Пользовательская модель

Один FVG-инструмент — уникальная комбинация биржи и торговой пары. Например, `BTCUSDT` на Binance и `BTCUSDT` на Bybit считаются двумя инструментами.

Для каждого инструмента сохраняются:

- биржа;
- нормализованный символ;
- таймфреймы;
- статус уведомлений;
- дата создания;
- фильтры цены и размера.

Для пар с базовым активом BTC доступны `15m`, `1h`, `4h`, `1d`. Для ETH, SOL и остальных не-BTC активов с бирж загружаются только свечи `15m`; старшие таймфреймы отсекаются до сетевого запроса.

Лимит составляет 10 инструментов на Telegram ID. Несколько таймфреймов одной пары занимают одно место. Проверка лимита и добавление выполняются внутри одной атомарной транзакции хранилища настроек.

## Миграция

Настройки FVG переведены на схему версии 3. При чтении старой схемы версии 2:

- старые символы считаются инструментами Bitunix;
- им назначается таймфрейм `15m`;
- сохраняются настройки модуля, направлений, пред-FVG и фильтров;
- старые Bitunix-ключи и идентификаторы событий сохраняются, чтобы обновление не вызвало повторную рассылку.

Миграция идемпотентна: повторное чтение уже нормализованных данных не создаёт дубликаты.

## Рыночные расчёты

Публичные свечи загружаются через единый адаптер для:

- Bitunix;
- Binance;
- Bybit;
- BingX;
- Bitget;
- Gate.

Планировщик формирует уникальный набор `биржа + символ + таймфрейм`, рассчитывает подтверждённый FVG один раз и затем выбирает всех подходящих получателей. Персональные фильтры не запускают повторный рыночный расчёт.

Политика загрузки:

- BTC: подтверждённые свечи `15m`, `1h`, `4h`, `1d`, а также `1m` для расчёта пред-FVG;
- не-BTC: только подтверждённые свечи `15m`;
- Bitunix WebSocket не подписывает не-BTC инструменты на минутный канал;
- Bitunix REST recovery не запрашивает минутные свечи не-BTC;
- мультибиржевой REST не запрашивает старшие таймфреймы не-BTC.

Подтверждённое событие создаётся только по трём последовательным закрытым свечам. Проверки выполняются на границах соответствующих таймфреймов.

## Пред-FVG

Пред-FVG остаётся исключительно 15-минутной функцией Bitcoin. Базовый актив определяется как `BTC`, поэтому поддерживаются пары наподобие `BTCUSDT`, `BTCUSDC` и `BTCUSD`.

Для остальных активов:

- настройка пред-FVG не показывается;
- рынок не попадает в список предварительного сканирования;
- минутные свечи не загружаются и не агрегируются;
- предварительное событие не создаётся;
- уведомление не отправляется.

## Доставка и защита от дублей

Существующий SQLite/WAL event store и persistent outbox сохранены. Уникальный идентификатор события включает биржу для новых площадок. Формат старого Bitunix ID не изменён.

Это обеспечивает:

- идемпотентную запись событий;
- отсутствие повторной доставки одному пользователю;
- сохранение очереди после перезапуска;
- повторные попытки при временных ошибках Telegram;
- прекращение повторов после постоянного отказа Telegram.

## Telegram-интерфейс

Добавление проходит последовательно:

1. выбор биржи;
2. ввод и проверка торговой пары;
3. выбор таймфреймов;
4. экран проверки;
5. явное подтверждение.

Карточка инструмента позволяет менять таймфреймы, ставить уведомления на паузу, управлять пред-FVG для Bitcoin и удалять инструмент.
